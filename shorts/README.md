# 드림그로우 쇼츠 제작

DJI 촬영본에서 로컬 음성 인식 → 편집표 작성 → 세로 화면/제목/자막 합성 → 음량 보정 → MP4 검증까지 수행한다.
첫 샘플은 `DJI_20260914072454_0008_D`, v2 기준 41.0초. 기존 `youtube/`는 다른 채널 소유이므로 이 모듈은 독립적으로 운영한다.

## 편집 원칙 (모든 영상 필수)

**착수 전 반드시 [`EDITORIAL.md`](EDITORIAL.md) 통독**. 10대 상시 규칙과 핵심 후킹 발굴 프로토콜이 있다.

1. **핵심 후킹 문구 반드시 살리기 — 가장 중요.** 통념 뒤집는 문장을 찾아 통째로. 사라지면 편집 반려.
2. **언어 도입부 제거.** 제목이 시각 후킹 역할. 원본 setup 잘라내고 핵심 후킹으로 즉시 시작.
3. **인용부호.** 발화 인용은 큰따옴표 `"..."`, 강조·생각은 작은따옴표 `'...'`. 인용이 여러 자막이면 첫/마지막에만 여닫음.
4. **자막-음성 싱크.** 자막이 발화보다 먼저 뜨지 않게. 렌더 후 재청취 필수.
5. **컷 끝음 정리 + 내부 무음 제거.** clip end는 문장 완결 직후. clip 내부 0.4초 이상 무음은 `silencedetect`로 탐지 후 clip 분할.
6. **컷 사이 0.3초 공백** — 스타일 `cut_gap` 기본값. clip별 `gap_after`로 오버라이드 가능.
7. **마지막 tail 여유 0.3–0.5초.** 마지막 clip에 `gap_after: 0.5`.
8. **하단 브랜드 = "드림그로우"** — job의 `brand` 필드.
9. **리드 마그넷 안내는 자료가 있을 때만.** 영상에 "댓글 주시면 보내드립니다" 안내를 넣으면 `lead_magnets/<주제>_v1.md`가 저장소에 실제로 있어야 한다.
10. **재생 속도 1.2배 기본** — 스타일 `playback_rate: 1.2`. 렌더러가 setpts+atempo로 최종 합성 시 축소.

## 편집 버전 관리

같은 원본에서 다른 목적의 편집을 뽑을 때는 job 파일명 뒤 `.v1.json`·`.v2.json`으로 병렬 관리한다.
예: `DJI_0008.v1.json`(짧은 편집), `.v2.json`(리드 마그넷 안내 포함). 산출물도 `artifacts/shorts/<원본>/v1/`·`v2/`로 분리.

## 현재 자동화 범위

- 자동: 한국어 단어 시각 추출, DJI 회전 정보 적용, 구간 자르기와 연결, 1080×1920 세로 구성, 제목/자막 이미지 생성, SRT 출력, 2패스 음량 정규화, 전체 디코딩 검증, 결과 기록.
- 편집 판단: 에이전트가 원문을 읽고 메시지를 선택한 다음 `jobs/*.json`에 구간·자막·구도를 기록한다. 임의의 새 영상에서 주제/구도를 스스로 선택하는 완전 무인 자동화는 아직 아니다.
- 이번 샘플은 에이전트가 원문과 렌더 화면을 검토했다. 향후 파일도 사실·어미·타이밍·오인식 확인이 필요하다. 발행은 이 프로그램의 기능에 포함하지 않는다.

## 실행

macOS Apple Silicon, Python 3.11 이상, FFmpeg/FFprobe(libx264/overlay/loudnorm), Pillow가 필요하다.
음성 인식에는 MLX Whisper를 사용하며 최초 모델 다운로드 이후 로컬에서 처리된다. 외부 API 키는 불필요하다.
글꼴은 `~/Library/Fonts/Pretendard-Black.otf`, `Pretendard-SemiBold.otf`를 사용한다.
다른 환경에서는 스타일 JSON의 글꼴 경로를 설치된 한글 폰트로 바꾼다.

저장소 루트에서 첫 샘플 재렌더:

```sh
python3 -m shorts.render render \
  --job shorts/jobs/DJI_20260914072454_0008_D.v1.json \
  --output artifacts/shorts/DJI_20260914072454_0008_D/v1
```

새 영상 분석:

```sh
python3 -m shorts.render prepare \
  --source '/absolute/path/DJI_새영상.MP4' \
  --output artifacts/shorts/새영상
```

`transcript.txt`와 `transcript.json`을 읽고 샘플 job을 복제한다. `source`에 새 영상의 절대 경로를 넣으면 `source_root/source_name` 검색보다 우선한다.
JSON의 `start/end`는 **모두 원본 영상의 초 단위 시각**이다. 자막도 원본 시각으로 지정하며, 렌더러가 출력 타임라인으로 변환한다.
자막은 최대 2줄, 줄바꿈은 JSON에서 `\n`으로 쓴다. 폭을 넘는 자막은 잘라내지 않고 오류로 알려준다.
`center_x`는 원본 너비에 대한 구도 중심 비율, `zoom`은 1 이상인 확대 배율이다.
컷 사이 공백은 스타일 `cut_gap`(기본 0.3초)으로 전체 적용하거나 clip별 `gap_after`로 오버라이드한다. 마지막 컷은 gap이 무시된다.
하단 브랜드 문구는 job의 `brand` 필드(기본 "드림그로우").

```sh
python3 -m unittest shorts.test_render
```

## 결과물

`artifacts/shorts/<영상>/v1/`:

- `dreamgrow_괜찮아보다_감정읽기_v1.mp4`: 완성 영상
- `captions.srt`: 타임라인에 맞춘 편집 가능한 자막
- `edit.json`, `style.json`: 이번 결과에 실제 사용한 편집표와 스타일 사본
- `manifest.json`: 원본 경로/수정시각/크기, 설정 해시, 출력 규격·검증 결과
- `work/`: 구간 영상, 자막 PNG, FFmpeg 로그. 원본과 스타일이 같으면 컷 캐시 재사용

원본은 수정하지 않는다. 대용량 파일과 음성 인식 결과는 git에서 제외되는 `artifacts/`에 둔다.
추적 대상은 코드, 스타일, 편집표, 제작 문서다. 게시·예약·메시지 전송은 수행하지 않는다.

## 계속 개선하는 방식

1. 사용자의 수정 요청을 `docs/shorts/CHANGELOG.md`에 기록한다.
2. 공통 스타일 수정은 스타일 버전을 올리고, 영상별 내용 수정은 job 버전을 올린다.
3. 첫 3–5편은 자막 오인식/줄 길이/컷 간격/얼굴 구도를 기준으로 다듬는다.
4. 이후 음성 구간 감지, 장면별 얼굴 추적, 자동 후보 구간 추천을 추가한다.
5. 승인된 편집 기준이 쌓이면 폴더 입력 큐와 처리 이력을 연결한다. 주기 실행·유튜브 업로드 연결은 별도 단계다.
