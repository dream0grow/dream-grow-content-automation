# 드림그로우 쇼츠 편집 원칙

이 문서는 **모든** 드림그로우 쇼츠 편집에 계속 적용되는 상시 규칙과 프로세스다.
개별 영상의 편집 노트가 아니라, `shorts/` 파이프라인이 뽑는 모든 결과물이 따라야 하는 기준이다.
`shorts/README.md`·`CLAUDE.md`·`docs/shorts/CHANGELOG.md`·`memory/`는 이 문서를 참조한다.
원칙이 바뀌면 여기부터 바꾸고 다른 곳은 따라온다.

## 10대 상시 규칙

**모든 쇼츠는 편집 착수 전에 이 목록을 확인한다.**

### 1. 핵심 후킹 문구를 반드시 살린다 — **가장 중요**

원본에서 **"사람들이 일반적으로 생각하지 못하는 부분을 짚는 문장"** 하나를 찾아 통째로 넣는다.
이 문장이 사라지면 편집은 성립하지 않는다.
후킹이 애매하면 편집을 뽑지 말고 사용자에게 어떤 문장을 살릴지 확인한다.

발굴 프로토콜은 이 문서의 [핵심 후킹 발굴 프로토콜](#핵심-후킹-발굴-프로토콜) 참고.

### 2. 제목 = 시각적 후킹. 언어 도입부는 제거

쇼츠에서 상단 제목은 그 자체로 강력한 시각적 후킹이다.
원본에 도입부(setup: "부모님들, 위로한다고 이렇게 말씀하시죠…" 같은 서두)가 있어도,
제목이 같은 정보를 이미 전달한다면 그 도입부는 **잘라내고 핵심 후킹으로 바로 시작**한다.
청자는 이미 제목을 읽었기 때문에 서두를 다시 들려주면 지루하다.

### 3. 제목·자막 인용부호 규칙

- **큰따옴표 `"..."`**: 발화 인용(실제로 한 말, 가상으로 들린 말, 예시 대사).
- **작은따옴표 `'...'`**: 생각·강조.
- 인용이 여러 자막으로 나뉘면 **첫 자막에 여는 따옴표, 마지막 자막에 닫는 따옴표**, 중간 자막은 부호 없이. 예:
  ```
  자막1: "너 감정 아무렇지도 / 않으니까    ← 여는
  자막2: 그냥 조용히 해"                    ← 닫는
  자막3: 라고 들리는 경우도 있어요          ← 화자 서술 (따옴표 없음)
  ```
- 제목에도 같은 원칙. 예: `"괜찮아. 별일아니야."` / `위로가 안되는 이유`.

### 4. 자막-음성 싱크

- **자막 시작은 실제 발화 시작 이전이 되지 않게** 한다. 자막이 먼저 뜨면 어색하다.
- clip의 `start` 자체를 발화 시작 시점에 정확히 맞추고, 필요하면 0.05~0.1초 뒤로 밀어 안전 마진 확보.
- mlx-whisper 전사의 타임스탬프는 가끔 이르거나 늦다. **렌더 후 재청취 검증 필수**.

### 5. 컷 끝음 정리 + 내부 무음 제거

- clip의 `end`는 **문장 완결 직후**로 둔다.
- 다음 발화의 잔음("계시죠? 죠?" 같은 반복)이 붙지 않도록 필요하면 0.05~0.1초 앞당긴다.
- 특히 종결어미(`~죠? / ~요. / ~다.`)로 끝나는 clip은 잔음이 붙기 쉽다.
- **clip 내부에 0.4초 이상 무음이 있으면 clip을 분할**해 그 무음을 잘라낸다.
- 검증: `ffmpeg -i speech.wav -af "silencedetect=noise=-25dB:d=0.15" -f null -` 로 무음 구간 자동 탐지. 차량 촬영처럼 노이즈 플로어가 높으면 `-20dB`로 완화. 감지된 각 구간을 편집표에 반영해 `end`/`start`를 이동하거나 clip을 두 개로 나눈다.
- 사례(DJI_0008): 원본 21.73–22.36(0.63s), 67.03–68.75(1.72s), 166.44–167.50(1.06s) 구간이 자동 탐지 → clip 분할·경계 이동으로 v2 iteration 2에서 제거.

### 6. 컷 사이 0.3초 공백

컷 편집 뒤 리듬을 위한 짧은 공백.
스타일 JSON `cut_gap` 기본값 0.3초 유지. 특정 컷에서 다르게 하려면 clip의 `gap_after` 오버라이드.
렌더러가 마지막 프레임 hold + 무음으로 확장한다.

### 7. 마지막 clip에 tail 여유 0.3–0.5초

영상이 뚝 끊기면 여운이 없다. **마지막 clip에 `gap_after: 0.5`**(짧은 마무리는 0.3) 로 tail hold를 둔다.
마지막 자막이 사라진 뒤 인물의 마지막 표정이 0.5초 정도 남고 페이드아웃되는 느낌.

### 8. 하단 브랜드 = "드림그로우"

`render.py`의 기본값과 job JSON의 `brand` 필드 모두 "드림그로우".
다른 채널을 위해 편집한다면 job의 `brand`만 바꾼다. 스타일 파일명(내부 사용)은 유지.

### 9. 리드 마그넷 안내 clip이 있으면 자료가 실제로 있어야 한다

영상에 "이 자료 받아가세요" 안내(원본 말미의 "댓글 주시면 보내드립니다" 같은 구간)를 포함시켰다면,
`lead_magnets/<주제>_v1.md`에 실제 자료가 **저장소에 존재**해야 한다.
- 관련 job의 `editorial_notes`에 파일 경로 명시.
- 초안은 md로 만들고 사용자가 수정한 뒤 PDF로 변환하는 흐름.
- 자료가 준비되지 않았다면 리드 마그넷 안내 clip을 편집에서 뺀다(약속을 어기지 않기).
- 원본에 안내 발화 자체가 없으면(DJI_0006처럼 설명만 하고 끝나는 촬영본) 마지막 clip의 `gap_after`를 3~4초로 늘리고
  그 hold 구간에 자막 cue를 얹어 **무음 텍스트 엔드카드**로 안내한다. 자막 cue는 clip `end + gap` 까지 허용된다.
  엔드카드 문구는 두 줄 이내·두 장 이내(질문 한 장 + "자료, 아무 댓글이나 남겨주세요" 한 장).

### 10. 재생 속도 1.2배 기본

쇼츠는 시청자가 빠르게 훑는 매체다. 정보 밀도와 시청 유지율을 위해 **재생 속도 1.2배가 기본**이다.
- 스타일 JSON `playback_rate: 1.2`에서 상속. job에서 오버라이드 가능(`playback_rate` 필드).
- 렌더러가 최종 합성 단계에서 `setpts=PTS/1.2` + `atempo=1.2`로 시간 축소. 원본 편집 시각(clip start/end, caption 시각)은 원속도 기준으로 그대로 쓰되, 최종 mp4만 짧아진다.
- SRT 자막의 시각은 편집 시각 기준(원속도). 최종 mp4에서는 1.2배 빠르게 흐른다.
- 범위 `[0.5, 2.0]` — ffmpeg atempo 한 단계 처리 한계.
- 배속이 어색한 영상(감성적 서정, 느린 낭독)은 job에서 1.0으로 되돌린다.
- 사례(DJI_0008 v2 iteration 2): 편집 31.9초 → 최종 재생 26.6초.

## 편집 버전 관리

같은 원본에서 다른 목적의 편집을 뽑을 때는 job 파일명 뒤에 `.v1.json`·`.v2.json`을 붙여 병렬 관리한다.
- 예: `DJI_0008.v1.json`(짧은 편집), `.v2.json`(리드 마그넷 안내 포함).
- 산출물도 `artifacts/shorts/<원본>/v1/`·`v2/`로 분리.
- job JSON 내부의 `version` 필드는 그 편집 내부의 iteration(자막 수정 등)을 나타낸다. 편집 목적이 바뀌면 파일명의 `.vN`을 올린다.

## 핵심 후킹 발굴 프로토콜

편집 착수 전 반드시 이 순서로 진행한다.

### 1단계. 전사 통독

`shorts/render.py prepare`로 뽑은 `transcript.txt`를 처음부터 끝까지 읽는다.
발화 흐름·주제 전환·반복 요약 위치를 확인한다.
오인식/빈 구간(예: DJI_0008의 106–123초)은 표시만 하고 넘어간다.

### 2단계. 후킹 후보 필터링

각 문장을 다음 특성으로 스코어링한다. **2개 이상 충족하면 후보로 표시.**

- **통념 뒤집기**: "일반적으로 X라고 생각하는데 실은 Y" 구조. 청자의 기존 인식을 흔든다.
- **구체적 대사·장면 재현**: 추상 설명이 아니라 "너 감정 아무렇지도 않으니까 조용히 해" 같은 실제 발화·상황.
- **감정적 각인**: 부모의 자책·안도·놀람·다짐 같은 반응을 유도.
- **짧고 강한 문구**: 8~15초 안에 완결되는 밀도 있는 문장.

### 3단계. 주 후킹 1개 확정

후보 중 "일반 상식 vs 새로운 인식"의 대비가 가장 선명한 것.
**판정 기준**: 이 문장이 편집에서 빠지면 영상의 존재 이유가 사라지는가? YES면 주 후킹.

### 4단계. 지원 문맥 확보

주 후킹 바로 앞뒤에서 반드시 필요한 setup(문제 제기)과 consequence(결과·의미)만 잘라 붙인다.
setup 없이 후킹만 넣으면 어리둥절, consequence 없이 넣으면 미완결.

### 5단계. 본론·결론 붙이기

후킹 뒤에 다음 3파트를 이어붙인다.

- **대안 제시**(무엇을 대신 해야 하는가): DJI_0008의 "아이의 상황과 상태를 말로 읽어 줘야 됩니다".
- **구체 예시**(실제 대사): "아, 너 지금 너무 속상했구나 / 무릎이 까지니까 진짜 아팠겠다".
- **결론**(왜 중요한가): "그 인정이 아이의 내면을 단단하게 만듭니다".

### 6단계. 반복 요약 제거

원본의 자기 요약("결국 이런 말입니다")이 후킹과 내용이 겹치면 제외한다.
DJI_0008의 32–41초 "괜찮아 별일 아니야 위로해 준답시고…" 구간이 그 예.

### 7단계. 자막 분할

- 자막 어순은 원음 유지. 띄어쓰기·문장부호만 정리.
- 반복 말버릇("그런 분들 그 말이"→"그런 분들, 그 말이")은 정리하되 삭제하지 않는다.
- 자막은 최대 2줄. 줄바꿈은 JSON에서 `\n`.
- 핵심 후킹 부분은 `zoom` 1.02~1.06으로 살짝 강조.

### 8단계. 재청취 검증

렌더 후 완성본을 처음부터 끝까지 청취하며 확인한다.

- 후킹이 살아있는가.
- 자막 오인식·타이밍 어긋남 없는가.
- 컷 사이 공백이 자연스러운가.

에이전트가 직접 들을 수 없으므로 **완성본 음성을 whisper로 다시 전사**해 `verification_transcript.json`으로 남기고,
단어별 시각을 원본 시각으로 역산해 각 자막 cue의 시작과 비교한다(0.2초 이상 자막이 앞서면 clip/cue 시작을 뒤로).
빠진 단어·clip 끝에 딸려온 다음 발화("지금" 같은 군말)도 이 비교로 잡는다. 차량 촬영처럼 노이즈 플로어가 높은 원본은
silencedetect가 무음을 못 찾으니 0.05초 RMS 프로파일을 찍어 경계를 본다.

## 사례 학습 — DJI_0008 v1 → v2

**v1의 실수**: 후킹을 놓쳤다.
원본 32–41초 "괜찮아 별일 아니야 위로해 준답시고 하는 말인데 아이들의 마음의 문이 닫힌다"만 쓰고 시작.
이건 영상의 **자기 요약**이지 **후킹**이 아니다. 청자의 통념을 뒤집는 힘이 약하다.

**사용자 피드백**: "너 감정 아무렇지도 않으니까 그냥 조용히 해 라고 들리는 경우도 있어요" (원본 15.62–23.74초)가 핵심 후킹.
사람들이 일반적으로 생각하지 못하는 부분을 짚기 때문.

**v2 반영**: 후킹 4문장(1.68–29.70초) 통째로 살리고, 반복 요약(32–41초)은 제외.
결과 41.0초, 자막 19개, 후킹 중심에 zoom 1.05 강조.

**교훈**: 원본의 자기 요약과 진짜 후킹을 혼동하지 말 것.
자기 요약은 발화자가 청자를 위해 "정리해 드리는" 문장이고, 진짜 후킹은 청자의 인식을 **흔드는** 문장이다.
후자는 보통 원본 앞부분(도입 5~30초)에 있다.

## 사례 학습 — DJI_0008 v2 → v3

**v2의 문제**:
- 초반부가 길었다(도입 setup 1.68–15.62초를 다 넣음).
- clip 1 끝(9.12초)에서 잔음 반복 "계시죠? 죠?"이 붙었다.
- 자막이 발화보다 살짝 먼저 뜨는 구간이 있었다.
- 마지막이 뚝 끊겨 여운 없이 종료.
- 제목이 부호 없이 밋밋했다.

**v3 반영** (사용자 피드백):
- **도입부 통째로 삭제**. 제목이 시각 후킹 역할을 하니 원본 setup 1.68–15.62초는 불필요. 15.62초 핵심 후킹으로 즉시 시작 (규칙 2).
- 제목에 큰따옴표: `"괜찮아. 별일아니야."` / `위로가 안되는 이유` (규칙 3).
- 인용 발화 자막에 여닫는 큰따옴표. 화자 서술은 부호 없음 (규칙 3).
- 잔음 문제는 clip 삭제로 자동 해소. 남은 clip들도 발화 완결점에 맞춘 end (규칙 5).
- 마지막 clip에 `gap_after: 0.5` — 마지막 자막(26.6초) 뒤 0.5초 tail hold로 자연스러운 마무리 (규칙 7).
- 결과: 27.1초, 자막 13개, 훨씬 압축적이고 임팩트 있는 후킹→결과→대안→예시→결론 흐름.

**교훈**: 쇼츠는 짧을수록 좋다는 관성이 있지만 그보다 중요한 건 **시청자가 어리둥절할 시간을 주지 않는 것**. 도입부에서 상황을 다시 설명하면 지루하다. 제목 + 즉시 후킹으로 3초 내에 "무슨 얘기인지" 인식되게 하고, 이후 흐름은 반박 불가한 논리로 밀어붙인다.

## 새 영상 접수 표준 흐름

```
1. 전사              python3 -m shorts.render prepare --source '...' --output artifacts/shorts/<영상>
2. 통독              artifacts/shorts/<영상>/transcript.txt
3. 후킹 발굴          이 문서 2~4단계 따라 주 후킹 1개 확정
4. 편집표 작성        shorts/jobs/<영상>.v1.json (후킹·대안·예시·결론 + cut_gap 상속 + brand 드림그로우)
5. 렌더               python3 -m shorts.render render --job ... --output ...
6. 재청취 검증        후킹 살아있는지 최우선 확인
7. 사용자 검토        피드백 반영 시 job 버전 올려 v2/v3로
```

원칙이 바뀌면 이 문서부터 바꾼다.
