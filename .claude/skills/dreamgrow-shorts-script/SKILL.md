# 드림그로우 쇼츠 대본 제작·보완 루프

한 편의 쇼츠 대본을 **쓰고 → 보여주고 → 고쳐서 → 확정·저장**하는 반복 루프.
대본 형식·문체는 이 저장소에 이미 확정돼 있다. 여기서 새로 짓지 말고 아래 재료를 그대로 쓴다.

## 0. 입력 유형 판별 (가장 먼저)

| 입력 | 모드 | 기본 출력 형식 |
|---|---|---|
| 주제·고민 한 줄 ("학습지 30분 붙잡는 아이") | **A 신규** | 표준 릴스 5블록 |
| 사용자가 쓴 **부분 대본** 붙여넣기 (한두 문단, 번호 목록, 미완성) | **B 보완** | 사용자 초안의 형식 유지 (말하기 대본) |
| 주제 목록 3편 이상 / "N개 뽑아줘" | **C 일괄** | 후킹 문장 표 → 승인 후 본문 |
| 기존 볼트 원고 파일명 + 수정 지시 | **D 수정** | 원고의 기존 형식 유지 |

애매하면 물어보지 말고 표대로 정한 뒤 "B 보완 모드로 진행합니다"처럼 한 줄로 알린다.

## 1. 매번 읽는 재료 (세 가지, 생략 금지)

1. `data/hook_patterns.md` — 후킹 공식·템플릿 12개·**절대 금지**(공포·돈·죄책감 후킹).
2. `data/youtube_voice.md` — 실측 보이스 프로필. 어미(`~죠`, `~잖아요`, `~거든요`, `~해보세요`),
   자문자답, 청자 반박을 먼저 말하고 받아치기, 자기 실패 고백, 이모지 없음, "첫째·둘째" 대신 "먼저·그다음".
3. `orchestrator/prompts.py`의 `HUMANIZE_RULES` — 번역투·기계적 병렬·피동 남발 금지.
   ```bash
   python3 -c "from orchestrator import prompts; print(prompts.HUMANIZE_RULES)"
   ```

그리고 **같은 카테고리의 기존 릴스 원고 2편**을 벤치마크로 읽는다(형식·길이·화면 지시 감각).
```bash
ls "vault/SNS 콘텐츠 제작 시스템/05 리뷰/대기/" | grep '^원고_릴스_<카테고리>_' | head
```
카테고리는 `orchestrator.obsidian_state.topic_category(주제)`로 정한다
(수학·독서·미디어·놀이·학습·학교·훈육·감정·기타).

### 중복 검사
같은 주제 원고가 이미 있으면 새로 쓰지 말고 알린다.
```bash
grep -l '<핵심 키워드>' "vault/SNS 콘텐츠 제작 시스템/05 리뷰/대기/"원고_릴스_* | head
```
있으면 "이미 있는 원고를 보완할지, 다른 각도로 새로 쓸지" 한 줄로 묻는다(그 외엔 묻지 않는다).

## 2. 두 가지 대본 형식

### 형식 A — 표준 릴스 5블록 (40~50초, 낭독 260~325자)
볼트 원고 132편이 모두 이 형식이다. 블록 제목·타임코드·화면 지시를 그대로 쓴다.
주의: 기존 원고는 낭독 600자 안팎인데 "약 42초"로 적혀 있다(실제 약 90초). 형식만 빌리고 길이는 아래 글자 수 기준을 따른다.

```
# 릴스 스크립트 (약 42초)

**[0~3초] 후킹**
"<통념 깨기 또는 뜨끔한 질문 한 문장>"
(화면: <첫 컷 지시> / 자막 굵게)

**[3~10초] 문제 공감**
<부모가 겪는 장면 2~3문장. "내 얘기다" 하게>
(화면: …)

**[10~25초] 핵심 인사이트**
<왜 그런지 원리 1개 + 교실에서 본 장면 1개>
(화면: …)

**[25~38초] 실천법**
<집에서 오늘 할 것 1~3개. 부모가 실제로 할 말을 따옴표 대사로>
(화면: …)

**[38~45초] 마무리 + CTA**
<한 문장 요약 → 댓글/저장 유도 → "아이가 …하길 바랍니다.">
(화면: …)
```
CTA는 "댓글 남기면 자료 전송" 리드마그넷형 또는 "저장해 두세요"형. 구독 구걸·공포 마무리 금지.
리드마그넷을 제안할 때만 `# 리드마그넷 제안`(이름·유형·내용 3줄) 섹션을 덧붙인다.

### 형식 B — 말하기 대본 (30~50초, 200~325자)
사용자가 직접 쓰는 초안 형식. 제목 한 줄 + 짧은 문장 연타. 타임코드·화면 지시 없음
(원하면 `(화면: …)`을 줄 끝에 덧붙일 수 있다).
```
1. <제목 — 부모 고민을 그대로 쓴 한 줄>
<후킹 한 문장>
<공감 1~2문장>
<원리 + 교실 장면>
<실천 1~3개>
<마무리 한 문장>
```

## 3. 보완 모드(B)의 철칙 — 사용자 문장이 우선

사용자가 붙인 대본은 **글감이자 문체 기준**이다.
1. **사용자 문장은 원문 그대로 둔다.** 맞춤법·띄어쓰기만 고친다(예: "안돼요"→"안 돼요"). 의미·표현·순서 불변.
2. **빠진 블록만 채운다.** 초안에 이미 후킹이 있으면 후킹을 새로 쓰지 않는다. 보통 빠져 있는 것은
   교실 장면(원리 뒤), 실천법(부모 대사 포함), 마무리 한 문장이다.
3. **덧붙이는 문장은 사용자 문장의 톤을 따른다.** 사용자가 "~해요"체로 썼으면 보이스 프로필보다
   사용자 어미를 우선한다.
4. **사례는 교사 경험의 일반화로 쓴다.** "6학년 한 아이가…"처럼 특정 아이·수치·연구를 지어내지 않는다.
   근거 인용(연구자 이름·숫자)은 사용자가 준 것이나 볼트 메모에서 확인한 것만.
5. **먼저 표시본, 그다음 깨끗한 최종본**을 보여준다. 표시본은 줄 앞에 `[원문]`/`[추가]`를 붙여
   무엇을 손댔는지 한눈에 보이게 한다. 최종본에는 표시가 없다.
6. 초안이 여러 편(번호 1, 2, 3…)이면 편마다 위 과정을 따로 한다. 편 사이 내용을 섞지 않는다.

## 4. 품질 체크 (보여주기 전에 스스로 확인)

- [ ] 첫 문장이 통념을 깨거나 뜨끔한 질문인가. 인사·자기소개·배경 설명으로 시작하지 않았는가.
- [ ] 한 편에 메시지가 **하나**인가. 두 개면 두 편으로 나눈다.
- [ ] 실천법에 부모가 실제로 할 말이 따옴표 대사로 들어 있는가.
- [ ] 공포·과장·죄책감("당신이 놓쳐서") 후킹이 없는가. 문제 제기 뒤 곧바로 해결로 넘어가는가.
- [ ] 이모지·"첫째·둘째"·번역투("~에 대해", "~를 통해")·"~다" 4연속이 없는가.
- [ ] 낭독 시간을 계산해 제목 옆에 적었는가: **초 = 낭독 글자 수(제목·화면 지시 제외, 공백 포함) ÷ 6.5**.
  목표 40~50초(260~325자), 60초(390자)를 넘기면 실천법 개수부터 줄인다.
- [ ] 마지막으로 `/im-not-strange-ai`(5,000자 이하 Fast)로 윤문을 통과시켰는가.
  윤문은 의미·수치·사용자 원문을 바꾸지 않는다. 바뀌었으면 되돌린다.

## 5. 보여주기 → 피드백 → 반복

대본을 채팅에 그대로 보여준다(파일만 던지지 않는다). 피드백을 받으면 지시된 부분만 고치고,
고치지 않은 부분은 그대로 둔다. "더 짧게"는 실천법 개수를 줄이고, "더 세게"는 후킹 문장을
통념 깨기 템플릿으로 바꾸되 금지 후킹으로 넘어가지 않는다. 사용자가 확정할 때까지 반복한다.

### 일괄 모드(C)의 순서
1. 주제별 **후킹 문장 + 핵심 메시지 한 줄**을 표로 먼저 보여준다(편당 두 줄).
2. 사용자가 고르거나 "다 써줘" 하면 본문을 쓴다. 한 번에 최대 5편, 넘으면 나눠서.
3. 중복 검사는 편마다 한다.

## 6. 확정본 저장 (볼트 → 추천·핑퐁 연결)

사용자가 "확정" 또는 "저장해줘" 하면 볼트에 저장한다. 저장하면 다음 두 자동화에 자동으로 걸린다:
매일 아침 릴스 추천(`vault_pipeline/reels_recommend.py`)과 텔레그램 답장 수정 핑퐁(`script_feedback`).

경로·파일명: `vault/SNS 콘텐츠 제작 시스템/05 리뷰/대기/원고_릴스_<카테고리>_<키워드+키워드+키워드>.md`
(키워드는 주제 첫 세 어절을 `+`로 잇는다. `orchestrator.obsidian_state._keyword_slug(주제)` 사용.)

```markdown
---
주제: <제목 한 줄>
카테고리: <학습|훈육|…>
채널: reels
상태: 리뷰대기
생성일: <YYYY-MM-DD>
출처: 사용자_초안_보완        # A 모드면 AI생성_Dream_Grow스타일, D 모드면 기존 값 유지
영상상태: 원고작성
검수상태: 통과
발행시간:
---

<대본 본문 — 형식 A 또는 B 그대로>
```

- 형식 B로 확정한 대본도 그대로 저장한다(추천기는 형식을 가리지 않는다).
- D 수정 모드는 **프론트매터 원문을 보존**하고 본문만 교체, `수정일:`만 갱신한다.
- 저장 후 `git add` → 커밋(`릴스 원고: <주제>`) → `git pull --rebase origin <브랜치>` → `git push -u origin <브랜치>`.
- 촬영이 끝난 원고는 사용자가 `상태: 발행완료`로 바꾸고 `05 리뷰/완료/`로 옮긴다(추천·알림에서 빠짐).
  이 스킬은 그 이동을 대신하지 않는다.

## 7. 예시

`examples/학습지_30분_보완.md` — 사용자가 붙인 5문장 초안을 B 모드로 완성한 실제 사례
(표시본 + 최종본 + 형식 A 변환 + 낭독 시간 계산). 1차 초안 428자(66초)를 306자(47초)로 줄인 과정까지 있다.
새 대본을 쓰기 전에 한 번 읽으면 길이·톤 감각이 잡힌다.
